# aigent bench

A benchmark of how cheaply and correctly an agent answers real codebase questions with the library's tools. Private,
never published, not part of the package build.

## What is in it

- **Generated repositories** (`src/generate`): deterministic from a seed, 300 (small) to 20,000 (huge) files, with
  planted needles and decoys for 14 families (file find, string search, theme, React, customer UI, GDPR API, bug hunt,
  traps, symbols, API routes, env vars, tests, dead exports, PII fields). The manifest of planted items is for ground
  truth and hint linting only; solvers never see it.
- **Ground truth** (`src/truth`): computed from the files alone by exhaustive scripts with their own lexer, clause reader
  and import resolver (mounted routers and dead exports are resolved through imports, not matched by name), tested to
  agree with the manifest and on hand-built collision cases, and to import nothing from the tools under test.
- **Task specs** (`tasks/*.json`, generated by `src/tasks/build-specs.ts`, never edited by hand): 25 tasks, each in four
  wordings (precise, vague, jargon, wrong terminology) plus a held-out wording on held-out seeds (1000, 1001). The prompt reader is checked
  only against the tuning wordings, and each of its cues must appear in one of them, so it cannot be fitted to the
  held-out wording; held-out specs (and their reference) are built only with `--held-out`. Each spec
  has a prompt, a broad scope, the ground truth, the decoys, the acceptance rule, a reference solution measured by the
  reference policy and budgets derived from it: target 1.5x, pass 4x, stretch 0.8x. Wall time budgets come from a
  declared per-size wall time (measured time is not deterministic).
- **Checker** (`src/check`): set precision/recall/F1, bugs matched by location (±3 lines) and cause class, criteria
  lists; decoy hits counted; a none-exist task accepts only `{"none": true}` or an empty file list. Efficiency tiers
  count only for correct answers.
- **Hint linter** (`src/lint`): fails when an answer path, a path segment (or any 6-character piece of one), a symbol or
  a distinctive string appears in a task's prompt, scope or context, or in the bench agent's persona and skillset.
- **Solvers** (`src/solvers`): scripted policies that play the model through the real agent loop and tools
  (`reference`, `naive`, `decoy`, `lazy`, and from Round 1 `optimised`), and a model solver (`createAigent` over
  Ollama, DeepSeek or Anthropic, selected by `BENCH_MODEL`). The model tier is opt-in and is not run by tests or CI.
- **Self-tests** (`src/self-tests*.tests.ts`, run by `npm test`): on every non-held-out spec the reference is correct,
  reproduces its committed measurement (so it sits at target by construction: the budgets derive from it) and finishes
  within the declared wall time, the decoy-falling and lazy policies fail, and the naive policy passes but
  misses target on at least 80% of specs; a deliberately broken checker makes them fail.

## Rounds and the gate

| round | change | median tokens | p90 tokens | p90 turns | write-up |
|---|---|---|---|---|---|
| 0 | baseline: plain `fs_list`, `fs_read`, `fs_search` | 3,885 (first recorded 3,737) | 14,936 | 3 | `results/round-0.md` |
| 1 | `fs_search` files/counts layers and relevance order | 3,862 (reference 3,882) | 14,936 | 3 | `results/round-1.md` |
| 2 | repository index and classification tags (`@anupheaus/aigent/tools/index`) | 4,844 | 5,151 | 2 | `results/round-2.md` |
| 3 control | the Round 3 policy with every Round 2 tool still offered | 4,569 | 4,912 | 2 | `results/round-3.md` |
| 3 | layered answers everywhere, `fs_read` + index only | 3,447 (first reported 3,429) | 3,790 | 2 | `results/round-3.md` |

Every round was re-measured after the slice-15 review fixes (index cards, route liveness, dead exports, skip reporting,
one walk per call, the none-exist check), with one repetition: the scripted tier is deterministic, so repetitions add
rows, not information, and the IQRs in the summaries are spread across wordings and seeds, not noise. Round 0's first
figures predate the `fs_search` schema growth; Rounds 1-3 compare against the reference on the current tools (3,882 /
14,936). The control shows where Round 3's gains come from: the median saving is the smaller tool set (with every tool
offered the Round 3 policy is 18% dearer than the reference at the median), the p90 saving is the index. The strategies
of both the reference and the optimised policy are written for the generator's conventions (`ApiRequest`,
`createTheme(`, `*Tokens`, the personal-data field list, `analytics`, `createRouter()`), so the numbers show what the
tools make possible on such code, not how the strategies generalise. The held-out set is run once, at the end
(`results/held-out.md`). Each round is tagged locally (`bench-round-N`, the first recordings). `budgets.json` holds the
Round 3 budgets (each spec's best run plus 15%, turns and tool calls only by whole steps; median tokens and p90 turns
likewise) and CI fails when the scripted tier regresses against them, when a budgeted spec did not run or when a spec
has no budget (`--gate`, `src/gate.ts`; `--gate` and `--write-budgets` refuse `--seed`, `--tasks`, `--fresh-seeds` and
`--held-out`). Policies:
`reference`, `naive`, `decoy`, `lazy`, `optimised-r1`, `optimised-r2`, `optimised`; tool sets: `round0`, `index`,
`optimised` (`src/harness/tool-sets.ts`).

## Running

```
npm run bench -- --tier scripted --repeat 3 --label my-run      # all non-held-out specs, reference and naive
npm run bench -- --policies optimised --tools optimised --gate   # what CI runs
npm run bench -- --policies optimised --tools optimised --write-budgets round-N   # only after a proven round
npm run bench -- --fresh-seeds 21,22                             # also rebuild the run variants on fresh seeds
npm run bench -- --held-out                                      # held-out specs only (milestones, never tuning)
npm run bench -- --build-specs                                   # regenerate the tuning specs in tasks/*.json
npm run bench -- --build-specs --held-out                        # rebuild the held-out specs (part of a held-out run)
BENCH_MODEL=ollama:qwen2.5-coder npm run bench -- --tier model   # a real model (not run here)
```

Results go to `results/<label>.json` and `results/<label>.summary.md`. Round write-ups are `results/round-N.md`.
