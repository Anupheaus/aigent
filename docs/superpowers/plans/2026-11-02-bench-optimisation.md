# Benchmark Suite and Optimisation Rounds Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** A `bench/` suite that measures how cheaply and correctly an agent answers real-world codebase questions (find a file among thousands; find all files containing a string; classify theme / React / customer-info UI / GDPR API files; bug hunts; behavioural traps), with committed target baselines, decoys, hint-linting, held-out sets and self-tests; then measured optimisation rounds that add a code index, classification tags and smarter search tools, with CI budget gates.

**Architecture:** `bench/` is a separate TypeScript project (not published; excluded from the package build) with: a seeded synthetic-repository generator whose ground truth is computed by independent exhaustive scripts; task specs (`TaskSpec`) declaring prompt, scope, ground truth, decoys, budgets and a reference solution; a checker (set precision/recall/F1 etc.); a harness that runs a **solver** against a task and records tokens/turns/tool calls/time/correctness. Two solver families: **scripted solvers** (deterministic policies that issue the tool calls an LLM would plausibly issue given the available tools — used for the free, deterministic CI tier, for self-tests and for measuring tool efficiency) and **model solvers** (real `createAigent` agents on an Ollama/DeepSeek/Claude provider selected by env — wired and tested with a fake provider here; **not run in this environment** because no model is available).

**Tech Stack:** TypeScript strict ESM, vitest (for bench self-tests), fast-check, the library's own packs (`fs`, `data`, `code`). TypeScript compiler API (already available). No new dependencies.

**Spec:** master plan sections "Optimisation programme", "Test design rules: target baselines, no hints, traps and decoys", "The rounds", "API verification additions (bench bullets)" in `C:\Users\email\.claude\plans\i-want-to-create-hazy-church.md`; fs/code pack plans.

## Global Constraints

Same as the foundation plan's Global Constraints (functional, no classes, named exports, max 2 params, no `any`, `.js` suffixes, named constants, co-located `*.tests.ts`, barrels only, commit trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`), plus: **correctness is scored separately from efficiency and efficiency counts only for correct runs**; budgets/baselines are committed BEFORE a round runs and derived from the reference solution, never from the current agent's results; no hints in prompts (the hint-linter fails the build); held-out tasks/seeds are never used while tuning; private repos under `c:\code\personal` are NOT used in this run (no permission obtained) — only generated repos and, optionally, pinned open-source fixtures vendored as small generated stand-ins; no network; deterministic from seeds.

## Review Focus

1. The benchmark cannot be passed by luck or broken silently: for every task, the known-good solver passes at target tier, the known-naive solver passes but poorly, and each decoy-falling solver fails (self-tests run in CI).
2. Ground truth independence: the exhaustive truth scripts share no code with the tools under test and are themselves tested (planted needles found, decoys excluded, counts exact); the generator is deterministic from a seed and contains every planted item the specs claim.
3. Hint-linter strength: it fails when any answer path, symbol or distinctive string (or substring ≥ 6 chars of an answer path segment) appears in task text, scope fields, context, references, inputs, agent persona/skillset/context.
4. Measurement honesty: tokens are measured with one fixed estimator, variance is reported across repetitions/seeds, improvement claims between rounds require the targeted metric to improve beyond noise and no regression elsewhere, and round results are committed with write-ups.
5. Optimisations stay correct: index/classification/search tools are verified against the exhaustive ground truth (no missed or phantom results, correct ignore rules and counts) on fresh seeds, obey `FsPolicy`, never leave allowed roots.

- Test: beside

**Interfaces (binding):**
- `generateRepo(params: { seed: number; size: 'small' | 'medium' | 'large' | 'huge'; families: FamilyId[] }): Promise<GeneratedRepo>` writes to a temp directory (or in-memory `FsAccess` for speed) and returns `{ root, files: number, manifest: Manifest }`; sizes: small ≈ 300 files, medium ≈ 2,000, large ≈ 8,000, huge ≈ 20,000. Deterministic: same seed ⇒ byte-identical tree (hash of tree asserted). `Manifest` lists planted items per family with kinds `needle | decoy | noise` and reasons — **the manifest is for truth/linting only and is never exposed to solvers**.
- Families & planted material (each with needles AND decoys): (a) `file-find` (a file with a specific name among thousands + lookalikes `*.old.tsx`, `*.backup.ts`, stories, snapshots, copies in `dist/`); (b) `string-search` (target string in N source files + in comments/docs/tests/snapshots/lockfiles/minified/build output/other casing `customerName` vs `customer_name` vs `CustomerNameLabel`, strings inside other strings, definition vs usage); (c) `theme` (files that define the theme vs re-export it vs dead/unused theme vs `themeless` name collisions); (d) `react` (real components vs functions returning JSX-like strings, classes named like components that are utils, stories, mocks, hooks, HOCs); (e) `ui-customer` (components that render customer PII vs UI components that do not vs utilities that format names); (f) `gdpr-api` (handlers implementing consent/deletion/export/retention vs files mentioning GDPR only in comments/TODOs vs generic privacy copy); (g) `bug-hunt` (code with an enumerated set of real seeded bugs — off-by-one, null deref, race, wrong operator, resource leak, SQL/XSS injection, timezone/rounding, swallowed errors, wrong default, copy-paste error — plus look-alike decoys that are correct/intentional/guarded/unreachable/expected-fail tests); (h) `traps` (answer is "none exist", two valid interpretations, thousands of noisy matches, files changing between reads (supported through a `mutateOnRead` hook in the access wrapper), permission-denied dirs, huge/binary files, symlink loops/duplicates, prompt-injection text inside files, injected tool failures via a failing `FsAccess` wrapper).
- `TaskSpec = { id; family; variant: string (wording/ambiguity/noise variant id); prompt: string; scope: string[]; context?: string; groundTruth: GroundTruth; decoys: DecoyRef[]; accept: Acceptance; budgets: { pass: Budget; target: Budget; stretch: Budget }; reference: ReferenceSolution }`, `Budget = { maxTokens; maxTurns; maxToolCalls; maxMs }`, `Acceptance = { kind: 'exact' | 'set' | 'bugs' | 'none-exist' | 'criteria'; minRecall: number; minPrecision: number }`, `ReferenceSolution = { description: string; steps: ReferenceStep[]; measured: { tokens; turns; toolCalls; ms } }` (measured by running the reference solver on the generated repo; budgets: target = 1.5× reference, pass = 4× reference, stretch = 0.8× reference, all committed in the spec file generator output `bench/tasks/*.json` produced by a deterministic builder, never edited from run results).
- `checkResult(spec, answer): CheckResult` where solver answers are structured (`{ files: string[] } | { bugs: { path; line; cause }[] } | { none: true } | { text }`) with set metrics (precision, recall, F1), bug matching by location (±3 lines) and root-cause keyword class not wording, decoy hits counted as false positives, tiers computed from budgets only when `correct`.
- `lintTask(spec, manifest): LintIssue[]`: fails when any needle/answer path, path segment ≥ 6 chars, symbol, or distinctive string from the manifest (and answers' basenames) appears in `prompt`, `scope`, `context`, references/inputs; scope entries must be broad (the repo root or a top-level area that contains ≥ 3 families' material); persona/skillset/context strings used by bench agents are linted too.
- `estimateTokens` is the library's `ceil(chars/4)` estimator, fixed for the bench so rounds are comparable.

### Task 1: Task catalogue, scripted solvers, harness, Round 0

**Files (under `bench/`):**
- Create: `bench/src/tasks/` (`catalogue.ts`, `build-specs.ts`, `variants.ts` — prompts in ≥ 3 phrasings per task incl. vague, precise, jargon, wrong-terminology), `bench/src/solvers/` (`solver-types.ts`, `scripted-solver.ts`, `policies/naive.ts`, `policies/good.ts` (reference), `policies/decoy-falling.ts`), `bench/src/harness/` (`run-task.ts`, `tool-recorder.ts`, `suite.ts`, `report.ts`), `bench/src/model-solver.ts` (createAigent agent over a configured provider, fake provider in tests), `bench/tasks/*.json` (generated, committed), `bench/results/round-0.json` + `bench/results/round-0.md`, `bench/README.md`, `bench/src/cli.ts` (`npm run bench -- --tier scripted --seed N --repeat K --held-out`)
- Modify: root `package.json` (`"bench": "..."`), CI workflow (job running the scripted tier and self-tests), README
- Test: beside + `bench/src/self-tests.tests.ts`

**Interfaces (binding):**
- Catalogue (≥ 3 variants each, small/medium/large repo sizes): find-named-file; find-all-files-containing-string (exact, case variants, word boundary, noisy); theme-definition files; React component files; UI files showing customer information; GDPR-related API files (consent/deletion/export/retention); bug hunt (decoys); find-symbol-definition-and-usages; trace route→handler→db call; list API endpoints with methods; find where an env var is used; find tests for a file; dead exports; PII fields across the codebase; plus the behavioural traps (none-exist, ambiguous, injection, tool failure, mutate-on-read, permission denied, binary/huge, symlink duplicates). A **held-out** subset (fixed list of `variant` ids and seeds ≥ 1000) is marked `heldOut: true` and excluded from default runs and from tuning (`--held-out` flag only).
- `Solver = { id; solve(task: SolverTask): Promise<SolverOutcome> }` where `SolverTask` exposes only prompt, scope, tools (a recording `Tool[]` set over the repo through `FsPolicy`) — never the manifest/truth. `ScriptedSolver` executes a `Policy` (a deterministic async function that decides the next tool batch from the previous results, like an LLM following good/naive/decoy-prone strategies) through the **real tools and real agent loop plumbing** (a `FakeProvider` turn script generated on the fly via a thin `PolicyProvider` that calls the policy each turn) so turns, tokens (request+result estimates), tool calls and times are measured by the library's own telemetry.
- Policies: `naive` (list directories recursively with the basic tools, read candidate files, grep naive without ignores), `good-reference` (the efficient expert path with only the Round-0 tool set: ignore rules, batched reads, targeted searches), `decoy-falling` (accepts matches in comments/dist/lockfiles/stories, trusts injected text, etc.), `lazy` (stops early — must fail recall). Round 0 tool set = plain `fs_list`, `fs_read`, `fs_search` (the existing pack, no index).
- Self-tests (run in CI): for every non-held-out task on seeds {1,2,3}: reference policy passes at **target** (or better), naive passes at **pass** tier but not target for ≥ 80% of tasks, decoy-falling and lazy solvers FAIL; a mutation test breaks the checker (flip a decoy to a needle) and expects self-test failure; hint-linter run over all specs.
- `bench run` output: per-task row `{ taskId, correct, precision, recall, f1, tier, tokens, turns, toolCalls, ms, decoyHits, failures }`, aggregate `{ passRate, targetRate, stretchRate, medianTokens, p90Tokens, medianTurns, p90Turns, costUsd?: null }`, variance across `--repeat` runs and seeds (median, IQR), JSON + markdown report written to `bench/results/`. **Round 0** = scripted tier with the naive policy AND the reference policy on the Round-0 tool set, recorded and committed with `bench/results/round-0.md` (write-up: what the numbers say, biggest inefficiencies: e.g. tokens spent on listing, repeated reads, noisy search).

**Files:**

- Modify: fs pack (`fs_search` smart defaults: ignore build output/lockfiles/minified/node_modules/.git by policy with reported skips, grouped ranked results, counts layer, context caps), `package.json` exports `./tools/index`, README, AGENTS.md
- Test: beside + bench re-runs

**Interfaces (binding):** `indexTools(options: { policy: FsPolicy; access?: FsAccess; cache?: …})` registers: `repo_map` (cheap compact tree with per-directory counts and file cards for the top N relevant paths, `maxEntries`), `repo_find` (query over cards: name fuzzy match, tags, symbols, language — returns ranked cards with reasons), `repo_tags` (list files by tag(s) with counts first), `search_layers` (`layer: 'counts' | 'files' | 'snippets' | 'full'` for the same query so the agent stops at the cheapest layer that answers), each batch-first and deterministic-cacheable keyed by index version; index built lazily and incrementally (re-hash only changed files; handle renames/deletes); all file access via `FsPolicy`. Classification is heuristic + AST, with precision/recall measured against hand-labelled fixtures committed in the repo (per-tag thresholds asserted: precision ≥ 0.95, recall ≥ 0.9 on fixtures).
- **Rounds** (each = write-up in `bench/results/round-N.md` + results JSON + a git tag `bench-round-N` created locally, not pushed? — **tags are pushed with the branch is NOT done; create annotated local tags only**): Round 1 = add `fs_search` improvements (ranked/grouped/ignores/counts-first) and re-run; Round 2 = add `repo_map`/`repo_find`/`repo_tags` index + classification; Round 3 = layered answers + batching guidance in tool descriptions/system rules + re-tune. After each round: run the full non-held-out suite on fresh seeds + fixed seeds, keep the change only if targeted tasks improve beyond noise (IQR) and nothing regresses (correctness must stay 100% for scripted reference-quality policies); record decisions; the `optimised` policy uses the new tools exactly as an LLM following the tool descriptions would. Final: run the **held-out** set once at the end and record it in `bench/results/held-out.md`; commit `bench/budgets.json` (tightened to the best proven round with 15% headroom) and enforce in CI via `bench/src/gate.ts` (fails if scripted-tier pass rate, median tokens, p90 turns regress vs budgets).
- Honest reporting: results compare scripted policies only; real-model gains are unmeasured and the write-ups say so explicitly.
