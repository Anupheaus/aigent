# AGENTS.md

## Purpose

`@anupheaus/aigent` is a TypeScript framework for AI tools, context, prompt, and memory orchestration.

## Commands

- `npm run typecheck` - type-check everything, including tests.
- `npm test` - run the vitest suite (`src/**/*.tests.ts`).
- `npm run build` - clean `dist/` (`scripts/clean.mjs`), then compile to it (tests excluded).

## Structure

`src/` folders (tests are co-located as `*.tests.ts`):

- `core` - `createAigent`, agent loop and run control, event stream, task input, system prompt and brief, errors, per-run telemetry wiring (`run-telemetry.ts`: creates the trace recorder and timer, builds and persists the run's records), model settings (`model-settings.ts` schema, `resolve-model-settings.ts` layering, `filter-provider-settings.ts` per-provider warnings) and the agent version hash (`agent-version.ts`, `canonical-json.ts`, `library-version.ts`, which must match `package.json`), provider resilience (`resilience-policy.ts` defaults/backoff, `stream-with-resilience.ts` retry and fallback, `first-event-timeout.ts`, `open-stream-iterator.ts` which opens a provider stream inside the caller's clean-up `try`, `open-turn-stream.ts` which wires them into a turn)
- `core` run setup and the shared loop: `run-agent-turns.ts` (the agent loop over initial messages, used by tasks and chat turns; keeps a cut-short round with `keepPartialRound`, reports committed rounds through `onCommit`, reads a `SteerSource` at each safe boundary), `run-task.ts` (task initial messages), `start-agent-run.ts` (sets up one run for either mode: routing, telemetry, planning, control, events), `finish-agent-run.ts` (limits, `RunSummary`, records), `drain-work.ts`, `turns-result.ts`, `run-control.ts` (stop modes and `sideEffectSignal`: side-effecting tools finish unless `force`), activity (`activity-update.ts` types, `activity-state.ts` pure derivation, `activity.ts` throttle and heartbeat publisher on its own real timers, `activity-options.ts`), `run-emitter.ts` (`thinking-done` and activity on every event), `run-callbacks.ts` (`onActivity`, `onThinking` (read from the run's thinking channel, independent of `showThinking`), `onToolActivity`), `resolve-agent.ts` and `model-targets.ts` (definition and provider resolution), `aigent-types.ts` (`AigentOptions`, `Aigent`), `ask-user-name.ts`
- `chat` - `agent.chat()`: the plain-JSON conversation model (`message.ts`, `conversation.ts`, `patches.ts`), the pure reducer (`reduce-conversation.ts`, `reduce-message.ts`), the patch log that is the only way a session changes (`apply-patch.ts`), `conversation-store.ts`, persistence (`session-persistence.ts` chunks and snapshots in collection `chats`, `chat-session.ts` load and wiring), the facade (`create-chat.ts`, `chat-closed.ts` (the closed-session error), `memory-runtime.ts` (the runtime view of a `persistence: 'memory'` chat: no store writes), `chat-send.ts`, `chat-navigation.ts`, `chat-feedback.ts`, `chat-options.ts`, public `chat-types.ts`), turn scheduling (`chat-engine.ts` with its closing state, `pending-turn.ts`, `message-queue.ts`, `requeue.ts` (the queue after a turn ends, `onStop: 'discard'`), `delivery.ts`, `steer-inbox.ts`, `user-messages.ts`, `turn-handle.ts`), one reply (`chat-turn.ts`, `turn-recorder.ts`, `finish-turn.ts`, `chat-brief.ts`), model-visible history (`lineage.ts`, `history-to-provider.ts` with tool-pair repair, `threads.ts`, `branches.ts`), questions (`ask-user-tool.ts`, `ask-user-checks.ts` (unanswerable or ambiguous questions), `question-state.ts`, `chat-questions.ts`, `task-questions.ts` for `TaskInput.onQuestion`), `attachments.ts` (collection `attachments`, by content hash) and `chat-title.ts` (a background request through `openTurnStream`, bounded and aborted by close). Test support: `chat.test-support.ts`, `chat-model.test-support.ts`, `reference-builder.test-support.ts`
- `providers` - provider interface and normalised request/event types, SSE parser and request helper, `openAiCompatible` adapter and its `deepseek`/`openai`/`ollama` presets, `anthropic` adapter (`anthropic-messages.ts` request mapping, `anthropic-stream.ts` event accumulator), settings mapping per adapter (`openai-settings.ts`, `anthropic-settings.ts`; `provider-settings.ts` lists every setting key; `provider-options.ts` keeps `providerOptions` from replacing fields an adapter sets), `retry-after.ts` (header parsing for `details.retryAfterMs`), `secret-redaction.ts` (credential redaction applied to every adapter error). `providers-end-to-end.tests.ts` drives `createAigent` through both adapters on mocked `fetch`; `live.tests.ts` hits real services and is skipped unless `AIGENT_LIVE=1` (plus `DEEPSEEK_API_KEY` / `ANTHROPIC_API_KEY` / a local Ollama server, see README "Live tests")
- `scheduler` - the shared `createScheduler` (`scheduler.ts`), its public types (`scheduler-types.ts`), options validation (`scheduler-options.ts`), per-key admission state (`key-state.ts`), lane and fairness order (`pick-next-waiter.ts`) and the sliding-window budget (`token-bucket.ts`). `fake-time.test-support.ts` is the fake clock and sleep for deterministic timing tests. The turn takes a lease per provider call in `core/leased-stream.ts`
- `tools` - strict tool definitions, registry, executor (`execute-tool-call.ts`: cache and shaping hooks; `envelope-text.ts`: the tool message text, safe for results JSON cannot represent; `run-tool.ts`: timeout and abort race; result sizing and `maxResultTokens` truncation in `truncate-result.ts`; `batch-entries.ts`: batch result helpers), `aigent_multi` (traces each inner call), activity renderer
- `telemetry` - stored record types (`run-record.ts`, `RUN_RECORD_SCHEMA_VERSION`) and their zod schemas (`run-record-schema.ts`), `trace-recorder.ts` (collects steps while the loop runs, no I/O), `run-timer.ts` and `measure-queue.ts` (timings), `build-run-records.ts`, `redact.ts`, `record-writer.ts` (the only path to the store: redact, then the keyed write queue), `persist-run.ts` (failures become one warning), `read-trace.ts`, `purge-records.ts`, `retention.ts`, `estimate-tokens.ts`, `summarise-args.ts`, `digest-args.ts` (per-run salted argument digest, `TraceStep.argsHash`, used for repeat detection)
- `cache` - tool-result cache: public types (`cache-types.ts`), `cache-key.ts` (key and schema hash), `tool-cache.ts` (lookup/store/abandon over the store and the keyed write queue), `single-flight.ts`, `cache-stats.ts` (pure stat updates), `cache-entry.ts` (entry building, servability), `cache-index.ts` (LRU eviction), `cache-options.ts`, `is-cacheable.ts`, `cache-findings.ts` (`report.cache`). The executor's cache path is in `tools/execute-tool-call.ts` (a miss always releases its single-flight); `tools/bounded-lookup.ts` bounds a lookup by the run signal and the tool timeout; `tools/run-tool.ts` runs a tool within its limits. `tool-cache.test-support.ts` is the harness for cache tests
- `context` - prompt hygiene and layout: `context-message.ts` (`ContextMessage`, the stored message with flags), `message-flags.ts` (kinds and default flags), `assemble-request.ts` (stored order + volatile block + breakpoints, layout check), `cache-breakpoints.ts`, `estimate-prompt-tokens.ts` (estimate and calibration), `context-budget.ts` (context size and usable budget), compaction: `compaction-policy.ts`, `compaction-groups.ts` (tool rounds as atomic units), `plan-compaction.ts` (pure stage planner), `apply-compaction.ts` (stubs, dedupe, summary and the hoist), `tool-result-stub.ts`, `summarise.ts` (fixed summariser prompt), `compactor.ts` (effectful, serialised per run; `context_overflow`), `volatile-block.ts` (the trailing `# Current state` request message and its options), `prefix-hash.ts`, `stability-monitor.ts` (warns once per run when the prefix changes). The run side is `core/run-context.ts` (the run's stored messages), `core/run-compaction.ts` (wires the compactor to the run and writes summaries through `openTurnStream`), `core/run-originals.ts` (the run's `result_original` store), `core/run-request.ts` (building each turn's request, prompt-size tracking) and `core/run-volatile.ts`
- `compression` - pluggable prompt compression: `compressor-types.ts` (public types incl. `PromptPreview`), `compression-options.ts` (validation, defaults, version input), `protect.ts` (protected spans), `compress-text.ts` (cache key, protected-span check, rejection), `compression-cache.ts` (store collection `compressed`), `compress-prompt.ts` (persona and task fields, records, preview rows), `compress-tool-results.ts` (dynamic, `compressible` tools), `fake-compressor.ts` (public test helpers), `eval-compression.ts` (A/B harness behind `ai.evalCompression`). The run side is `core/prompt-texts.ts` (system prompt and brief as sent, shared by runs and `core/preview.ts`), `core/static-prompt.ts` (per-agent memo) and `core/run-compression.ts`
- `planning` - consumer plan and agent todo: `plan-schema.ts` (validation and types), `plan-state.ts` / `todo-state.ts` (the only state transitions, shared by tools and directives), `run-planning.ts` (per-run state, events, volatile extras and corrections), `plan-complete-tool.ts`, `todo-tool.ts`, `render-pinned.ts` (pinned definitions and status sections), `apply-directives.ts`. The run side is `core/run-planning-setup.ts` (registry, pinned message sync, final status)
- `shapers` - verbatim-safe result shaping: `shaper-types.ts` (`ContentKind`, `Fidelity`, `Shaper`), `shaper-registry.ts` (validation, built-in order), `run-shapers.ts` (pipeline and per-run `ShapingState`), `original-store.ts` (handles), `result-original-tool.ts`, `alias-table.ts` (aliases and `expandAliases`; `core/expand-call-aliases.ts` applies it only to tools with `acceptsAliases`), `shapers-setting.ts` (`shapers` validation), `builtin/` (one file per built-in shaper). `verbatim-corpus.test-support.ts` holds the tricky-file corpus the verbatim tests run. The run side is `core/run-shaping.ts`; `scoring/shaper-findings.ts` adds `net-negative-shaper`
- `store` - store contract (optional `delete` and `purge`), in-memory store, keyed write queue
- `feedback` - `enableFeedback` resolution (`resolve-enable-feedback.ts`), the prompt addendum, the `aigent_feedback` tool and its per-run collector, stored feedback record types and collection names (`feedback-records.ts`), user feedback (`user-feedback-schema.ts` validation, `user-feedback.ts` storing it via the `responses` index and setting `userVerdict`), `previous` parsing (`previous-outcome.ts`) and the schema wrapper that adds it (`with-feedback-fields.ts`). The loop side lives in `core`: `link-previous.ts` strips and links `previous`, `dispatch-tool-call.ts` starts each call, `build-agent-registry.ts` adds the built-in tools
- `scoring` - `ai.report()`: public types (`report-types.ts`), pure `scoreRuns` (`score.ts`, `score-reliability.ts`, `score-format.ts`) against the rolling baseline (`baseline.ts`), per-run figures (`run-metrics.ts`, `pricing.ts`, `stats.ts`), findings (`findings.ts` over `tool-findings.ts`, `run-findings.ts` and `context-findings.ts` (`frequent-compaction`, `compression-net-negative`), with `finding-rules.ts` and `work-steps.ts`), `report-filter.ts`, `compare-versions.ts`, `agent-feedback-summary.ts` (`report.agentFeedback`), `agent-report.ts`, `report.ts` (pure assembly) and `read-report.ts` (store reading). `fixtures.test-support.ts` builds run records and traces with known numbers
- `analysis` - request analysis for `ai.report()`, pure functions over runs with their steps: `trace-group.ts` (similar-task grouping), `request-efficiency.ts` (cheapest successful path, typical cost, saving), `wasted-steps.ts`, `sequence-mining.ts` and `tool-suggestions.ts`. `analysis-fixtures.test-support.ts` holds the flailing and direct "find a file" runs
- `resume` - resumable instances: checkpoint record types and collections (`checkpoint-types.ts`), the append-only writer with snapshots, deltas and pruning (`checkpoint-writer.ts`), the bounded reader (`checkpoint-reader.ts`: head, latest snapshot, tail), schema upgrades (`migrations.ts`), the per-run call ledger (`call-ledger.ts`, written `started` before a tool runs), instance leases (`lease.ts`) and the fenced store that rejects a stale owner's writes (`fencing-store.ts`). the instance runtime (`instance-runtime.ts`: leases, fenced writers, the instance record, interrupted runs loaded at open), per-run hooks (`checkpoint-hooks.ts`), what a resumed run loads and how it starts (`prepare-run-resume.ts`, `agent-resume.ts` behind `agent.resume`), and `reconcile-calls.ts` (completes the interrupted round from the ledger by each tool's `resume` policy). The loop side is `core/run-checkpointer.ts`; the ledger write before a tool runs is in `core/dispatch-tool-call.ts`; chat suspension is `chat/suspended-turns.ts` and `chat/engine-questions.ts`. `checkpoint.test-support.ts` and `crash-injection.test-support.ts` (crashable store, scripted model, counting tools) hold the harnesses. Tool `resume`/`verify` validation is in `tools/tool-policies.ts`
- `approvals` - human approvals: public types (`approval-types.ts`), `approval-rules.ts` (`requiresApproval` evaluation, deny-beats-allow rules, `allow_always` scopes), `approval-gate.ts` (per-instance center: the gate the run calls before a tool runs, pending requests, `agent.approve`, restored requests) and `audit-trail.ts` (collection `approvals`). The gate sits in `core/dispatch-tool-call.ts` (before the ledger write) and in `resume/reconcile-calls.ts`; `core/run-agent-turns.ts` checkpoints pending requests (boundary `approval`)
- `guardrails` - the guardrail pipeline: public types (`guardrail-types.ts`), `define-guardrail.ts`, `pipeline.ts` (stage order, rewrite chaining, first block, timeouts and fail mode; synchronous while every check is), `stream-holdback.ts` (secret-aware hold-back of streamed text), `guardrail-options.ts` (validation), `map-strings.ts`, `stored-decisions.ts`, and `builtin/` (`secrets.ts`, `pii.ts`, `injection.ts` (also `neutraliseInstructions`, used by compaction summaries), `scope.ts`, `loop-guard.ts`, `output-schema.ts`, `index-builtins.ts` with `defaultGuardrails`). `fixtures.test-support.ts` holds the secret, PII and injection corpora. The run side is `core/run-guardrails.ts` (per-run checks, decisions, events), `core/guard-run-input.ts` (the input stage), `core/settle-answer.ts` (output stage and the structured-output retry loop); the call points are `core/dispatch-tool-call.ts` (toolCall and toolResult, also for `aigent_multi` inner calls) and `core/run-turn.ts` (stream); `scoring/guardrail-findings.ts` reports blocks
- `streaming` - chunk-safe `::aigent` directive parser and schemas
- `testing` - `FakeProvider` helpers and the fake compressors, public as `@anupheaus/aigent/testing`. It must never load vitest (`testing-entry.tests.ts` checks its import graph).
- `testing/contract` - the vitest-based `describeProviderContract` suite every provider must pass, public as `@anupheaus/aigent/testing/contract` (vitest is an optional peer dependency)

Test-only helpers shared between test files are named `*.test-support.ts` (excluded from the build, never exported), e.g. the fake `fetch` and the OpenAI and Anthropic SSE fixtures in `providers`.

Public entry points are the barrels `src/index.ts` (`@anupheaus/aigent`), `src/testing/index.ts` and `src/testing/contract/index.ts`; `src/public-api.tests.ts` pins their exact runtime exports.

## Rules

Read `C:\code\personal\agents\agents.md`, `C:\code\personal\agents\coding-standards.md` and `C:\code\personal\agents\patterns.md` first.

- ESM only, Node 20+, TypeScript `strict`, `module`/`moduleResolution` `NodeNext`: relative imports end in `.js`.
- Functional style: no classes, no `this`. Named exports only. `index.ts` files are barrels only.
- 2-space indent, single quotes, semicolons, trailing commas, blank line at end of file, numeric separators (`60_000`).
- No `any`. Explicit return types on exported functions. Max 2 parameters per function; use an options object for 3+.
- Descriptive loop variable names (no `i`, `item`). No magic values: use named constants. JSDoc on exported interfaces/fields.
- Tests co-located as `*.tests.ts`, vitest. Comments explain why.
- Errors via `createAigentError` only. Error messages include ids/values and what was expected.
- Commits: small, local only, on branch `phase-1-foundation`. End each commit message with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Never push. No downloads other than npm packages named in Task 0.
